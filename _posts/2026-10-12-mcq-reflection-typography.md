## AP CSP Strengths & Weaknesses Analysis

### Two Things Right

**My conceptual understanding is solid**
- Great at abstract concepts (algorithms, data representation, Boolean logic, iteration)
- I understand the WHY behind computing principles

**My data & information handling**
- Data compression, extracting info from data, using programs with data
- I can work WITH data once it's in front of me

### Two Things Wrong

**Procedures (calling & developing)**
- Calling Procedures and Developing Procedures are my weak spots
- I notice that I can't remember the syntax/steps to build or call procedures later

**Error identification & correction**
- I understand what code should do, but debugging/fixing broken code is harder

## What I Know vs. Don't Know

**I Know:**
- How to think algorithmically
- Data structures (lists, dictionaries, variables)
- Conditional & loop logic

**I Don't Know:**
- How to execute procedures from memory
- The exact syntax when writing code on my own (without reference)
- How to trace through broken code and fix it

## The Main Problem

- I can recognize correct code when I see it
- I struggle to produce code from scratch under time pressure
- Procedures are the linchpin — they're the hardest for me to memorize AND the most abstract to write

## Future Work

**Procedure drills:**
- Practice code repeatedly until muscle memory takes over (not just reading examples)
- Practice writing code without reference materials and write procedures without looking

**Debugging exercises:**
- Get comfortable fixing broken procedure calls/definitions

## My Class vs. Exam Steps and Reflection

- **In class:** I struggle to reproduce procedures from memory during live coding
- **On the CB exam:** I score lower on procedure units but higher on recognition/conceptual questions
- **Fix:** My weakness in class IS my weakness on the exam — they're the same problem
